# Stress test and red-team audit — round 4 (v2.2)

Date: 15 Nov 2026 (IST). Scope: the whole kit — `docs/ARCHITECTURE.md`, `CURSOR_PROMPT.md`, `AGENTS.md`, `docs/FLOWCHART.md`, `.cursor/rules/`, diagrams, `render.yaml`, `frontend/vercel.json`, `.env.example`, `backend/requirements/`, `supabase/` (config, migrations, tests), `data/samples/`, CI workflows.

Method: (1) cross-document consistency sweep with scripted checks (every `§n.m` reference resolves; every endpoint in CURSOR_PROMPT exists in ARCHITECTURE; tables in ARCHITECTURE vs migrations; env vars in docs vs `.env.example`/`render.yaml`; referenced kit files exist; YAML/TOML parse); (2) ML-integrity review; (3) scale/ops/security review, with the migrations and pgTAP tests executed on a throw-away Postgres (`tests/db_harness/run_db_tests.py`: 6/6 migrations applied, 14/14 assertions passed); (4) UX review; (5) comparison with PyCaret, AutoGluon, H2O, DataRobot, Orange, KNIME, Weka, MLJAR, Dataiku and Vertex AI (ARCHITECTURE §46.5). Hosting limits were checked against the Render and Supabase docs on 15 Nov 2026.

> **v2.3 note (16 Nov 2026):** the backend target is now a Contabo Cloud VPS (`docs/DEPLOY_CONTABO.md`); Render is the alternative / legacy path. The Render-specific findings carry over as follows: **ST-OPS-04** → the SSH `deploy` job runs only after `migrate`, there is no auto-deploy on the VPS; **ST-OPS-05** → `lab-beat` is a compose service running maintenance hourly; **ST-CON-02** → `q.predict.heavy` runs on the `worker-train` container (worker-train image); **ST-CON-05** → the env matrix lives in `/opt/arw-ml-lab/.env` (DEPLOY_CONTABO §7); **ST-CON-11** → `docker-compose.prod.yml` must match DEPLOY_CONTABO §5; **ST-OPS-11** → DEPLOY_CONTABO §12 GPU refusal (`LAB_GPU_WORKER=false`, HTTP 422) is offline-tested via `labcore/ops/gpu_worker_contract.py`. New VPS risks (single host, self-managed patching, 8 GB RAM) are covered by DEPLOY_CONTABO §3, §10–§12 and ADR-contabo; re-test them in Phase 8.2.

Normative result: ARCHITECTURE **§46** (and §45 for prediction). Status values: **fixed** (changed in the kit), **fixed + tested** (also verified by a test run in this audit), **specified — build in <phase>** (the spec and AC now require it; code does not exist yet), **open** (left for a named phase), **accepted** (deliberately not done).

## Not verified in this audit

* Render Blueprint sync, Vercel build and Supabase hosted behaviour were checked against documentation, not deployed (nothing is deployed from the kit).
* The pgTAP checks ran on plain Postgres 16 (pgserver) with a minimal Supabase stub and pgTAP shim, not on the Supabase CLI stack; `supabase test db` in CI is the authoritative run.
* Lock files were resolved, but the packages were not installed into a Render image.
* Performance targets (p95 latency, 1 M-row scoring memory) are design targets to be measured in Phases 3A and 8.2; no numbers are claimed here.
